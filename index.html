Trouble Shooting 대표 문제해결 사례
“암호화하되 검색 가능”한 개인정보 저장 Novartis Kisqali
문제환자 개인정보(PII)를 KMS로 필드 단위 암호화하자, 카카오 식별자로 회원을 조회·중복 확인하는 기능이 동작하지 않음
원인일반적인 랜덤 IV 암호화는 같은 평문도 매번 다른 암호문이 되어, DB 인덱스·유니크 제약으로 검색할 수 없음
해결검색 키가 되는 카카오 식별자는 결정적(deterministic) 암호화로 저장해 인덱싱·유니크 제약을 유지하고, 그 외 민감정보는 랜덤 IV로 저장해 보안 강화. 암호화 속성은 직렬화(응답)에서 제외
결과개인정보 필드 암호화라는 규제 요구를 지키면서도 회원 조회·중복 검증이 정상 동작 — 보안과 기능을 동시 충족
메일 오픈/클릭 통계 정확도 확보 Merck Saizen
문제HCP에게 발송한 리포트 메일의 ‘열람’ 통계가 실제보다 부풀려져 신뢰할 수 없었음
원인클릭 이벤트가 3개 지점에서 각각 기록되고, 새로고침·브라우저 프리페치·PRG 리다이렉트마다 중복 삽입됨
해결/hcp/enter/{token} 클릭 브리지 리다이렉트 패턴을 도입해, 실제 클릭 1회당 정확히 1건만 기록되도록 기록 지점을 단일화
결과“1클릭 = 1오픈”을 보장하여 메일 오픈/클릭 통계 신뢰도 확보
카카오 알림톡 발송 조건 이슈 개선 노보노디스크 환자지원
문제환자에게 발송되는 카카오 알림톡이 의도한 발송 대상·시점과 다르게 나가는 문제가 반복 발생
원인교육 예약·회원 상태에 따른 발송 대상·시점·순서 조건이 여러 곳에 분산되어 있어, 상태 변화와 발송 트리거가 어긋남
해결알림톡 발송 조건·순서·내용을 재정비하여 발송 대상 필터와 트리거 시점을 명확화하고 발송 로직을 정리
결과환자 대상 알림톡이 의도한 조건에서만 정확히 발송되도록 안정화 — 규제 민감한 환자 커뮤니케이션 신뢰도 확보
SSH 없는 완전 자동 배포 설계 Novartis Kisqali
문제서버에 SSH를 열어두는 배포는 보안 리스크·키 관리 부담이 크고, 수동 배포는 휴먼 에러가 발생
원인SSH·장기 자격증명 기반 배포 방식의 구조적 보안·운영 부담
해결GitHub Actions에서 AWS OIDC 키리스 인증으로 아티팩트를 S3에 업로드하고, AWS SSM으로 구성된 서버가 이를 받아 배포하도록 설계 — 인바운드 SSH·장기 자격증명을 제거
결과완전 자동화로 배포 휴먼 에러를 제거하고 공격 표면을 축소, dev/prod 분리 운영
